## 1. 目的と利用者

- 目的: Jw_cad(JWW)をインストールできない端末(利用者のスマホ Samsung Galaxy Z Fold5)で、ブラウザだけでJWW図面を開き、見る・書き込む・編集する・3Dにする。
- 利用者: トモ(香川大学 医学部附属病院 施設課、機械設備担当。公共建築工事の設計・積算・工事監理)。扱う図面は、機械設備(給排水衛生)の平面図・系統図と、大きな建築図面。
- 配信: GitHub Pages(`main` ブランチのルートをそのまま公開)。リポジトリ `tomo57810-maker/jww-reading`(公開)。インストール型(PWA)でも使う。
- 守るべき前提: **原本のJWWは絶対に書き換えない**。編集・注釈・3D部品は、別の「記録」として保存する(非破壊)。

## 3. 画面の使い方(最短)

- ツールバー: 移動 / 選択 / 図形(線・矩形・円・矢印) / 文字 / 測定(寸法・面積・ルート) / 壁3D / 基準点 / 赤ペン / コメント。
- 選択モードで図形を選ぶと、副ボタン(追加選択・壁を自動選択・基点移動・伸縮・↺↻・×1.25・×0.8・3D化・複製・削除)が出る。
- 図形・文字の消去は、「選択」→「削除」(「消す」ボタンは廃止。`erase` モードのコードは残してある)。
- 右上の「3D」で3D表示。「部品一覧」から部品を削除。

## 5. 重要な設計(壊さないこと)

1. **非破壊の編集モデル**: `EditStore` が、原本の図形(`ezjww`で読み、ブロック展開した平坦な配列)に「操作」を順に当てはめる。図形の番号(配列の添字)は変わらない(消した図形は `null`)。保存は、操作の記録(JSON)。`baseCount`(原本の図形数)が違うと、番号がずれるので読み込まない(`unloadedEdits` に生のまま保持して、上書きで失わない)。
2. **保存の単位**: 図面ごとに、中身のSHA-256をキーにする。保存した状態=`sha256:<hash>`、下書き=`draft:<key>`、表示位置=`view:<key>`(meta)。スナップショットは `{settings, items(注釈), edits, parts}`。変更の有無は `coreOf()` で判定(`items, scale, ops, parts` を含む)。
3. **3D部品**は、図形の番号(`ids`)で結びつく(平面図の図形を動かすと3Dも追従)。「壁3D」の部品だけは、なぞった点(`path`)を持ち、図形とは結びつかない。座標は用紙mm→実寸は縮尺をかける。3Dの座標は、メートル・Y上向き・Z=平面図のYの逆。
4. **「戻す」の順序**: `history` 配列("ann"/"edit"/"part")で、新しい順に戻す。
5. **選択モードの振り分け**(`ToolController.down`): 基点移動・伸縮の途中と、選択中の図形の角・○の取っ手は図面の図形(`ObjectTool`)へ。それ以外は、まず注釈(コメント・基準点など)を探し、無ければ図形のツールへ。
6. **ezjwwの座標・形式**: 用紙mm、Y上向き。TEXTは `x,y,end_x,end_y,height,width_factor,rotation,content,style`。SOLIDは頂点の順が 1,2,4,3。線種は `JWW_*`・`SXF_USER_*`・`CONTINUOUS`。レイヤ番号は `dxf.layers[グループ×16+レイヤ]`。

## 6. 開発・確認・公開の手順

```bash
cd jww-reading
npm install            # 初回のみ
npm test               # 70件
node scripts/serve.mjs # http://localhost:8080 (バックグラウンドで)
```

- **画面部品を変えたら**: `sw.js` の `CACHE` の版番号を上げる(現在 `jww-reading-v23`)。新しいJS/vendorファイルは `SHELL` の一覧にも足す(足し忘れるとオフラインで動かない)。
- **ブラウザ確認**: Playwright(`/opt/node-tools/node_modules/playwright`、Chromiumは `/opt/pw-browsers/chromium`、`executablePath` を指定)。タッチは CDP の `Input.dispatchTouchEvent` を使う。3Dは `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader` を付ける。図面は `input#file` へ `setInputFiles`。ページを `?debug` で開き、`window.__jww` で内部状態を見る。サーバーはターンをまたいで生きないので、同じコマンドの中で起動する。
- **公開**: ブランチ `ccr-7b922547-aznm1m` に、コミットして、`git push -u origin ccr-7b922547-aznm1m` と `git push origin ccr-7b922547-aznm1m:main`(GitHub Pagesは `main` を配信)。**利用者が頼まない限り、Pull Requestは作らない**。

  `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` と `Claude-Session: <セッションのURL>`(その時のセッションのURLに置き換える)。

## 7. 既知の制限・未了

- **JWWへの書き出しは未実装**(DXFは可)。`ezjww` にJWW書き込みはあるが、「新規作成」と「読み込んだ文書の変換(`toWriteDocument`)」の形で、編集後の図形を元の図面へ戻すには、色・線種・レイヤの対応表づくりが必要。
- 3D: 線・円弧・円のみ。配管は水平の管と、円の位置の立上りだけ(斜め・高さが変わる管はなし)。床・天井の面、窓・扉の開口、階(高さ)の管理は未実装。壁は、線の両面を別々に立ち上げる(1つの箱にまとめる処理は未実装。次の候補)。
- 壁の自動検出: 実際の図面(壁の線が複数レイヤに散らばり、仕上げ線が重なる)では、取りこぼしや余計な線が出る。条件(厚み・長さ・水平垂直・レイヤ除外)をダイアログで調整できる。調整の材料は、利用者の画面と、図面ごとの描き方。
- 描き足した文字の中身は、あとから書き換えられない(削除して打ち直し)。
- `SXF_USER_*` 線種は画面で実線表示。線の太さはDXFに出ない。
- 文字の「文字種」は、値を引き継ぐだけで、見た目のフォントは変わらない(図面の文字はすべて `STANDARD`)。
- OneDrive直接接続は、大学のMicrosoftアカウントでEntraのアプリ登録ができず未稼働(`docs/ONEDRIVE.md`)。個人所有のSurface(大学に登録済み)から登録する案が出ていたが、未着手。OneDriveアプリの「共有」はリンクしか渡さないため、「保存」してから開く運用。
- **実機(Z Fold5)での確認が未了の機能**: 保存・下書きの再開、自動で前回の図面を開く、基準点の削除、属性取得、文字、矢印、選択の一本化、DXF書き出し、3D表示とタッチ操作、壁3D、壁の自動選択。利用者から不具合の報告が来たら、画面の写真と一緒に原因を調べる。
